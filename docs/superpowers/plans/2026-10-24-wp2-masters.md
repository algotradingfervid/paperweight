# WP2 Masters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Run it under `docs/superpowers/plans/2026-10-25-execution-protocol.md` (roles, risk tier per task, review cadence; CD-96).

**Goal:** Build every master in `internal/masters/` (company and branch, party, address and contact, item, UoM and conversion, tax code, project, site, employee, expense type, payment terms) plus `internal/masters/gstin`, wire them into the kernel's registry, list, CSV import and screens, and switch the test kit's canonical seed from the Wave 1 stand-in tables to the real masters.

**Architecture:** One package per master, each with its own migration block, `sqlc` queries and a `Service` whose write methods run inside `db.Write`. A small shared package, `mstkit`, holds the rules every master shares (code, name, version check, audit, disable, delete-if-unreferenced) and is the only place that calls kernel write APIs, so a kernel name that differs from this plan is fixed in one file. Masters register with the DocType registry (`internal/kernel/doctype`) as **non-submittable DocTypes with a `Master` lookup** (CD-21, decision M1 below) so the kernel's link checks, list, picker, export, import, rights matrix and generic screens work for them without the kernel importing `masters`. MST also supplies the kernel's two directory-style interfaces: `auth.Directory` (CD-13) and `print.Letterhead` (CD-30).

**Tech Stack:** Go 1.27.3, `modernc.org/sqlite` v1.61.0, `sqlc` v1.31.1, `pressly/goose/v3` v3.29.0, `a-h/templ` v0.3.1070, `go-chi/chi/v5` v5.5.0, htmx 2.0.11, `google/go-cmp` v0.7.0. No new third-party modules: GSTIN, PAN, pincode and HSN rules are ported from India Compliance (about 150 lines of tables and checks; no maintained Go library implements them), email parsing uses `net/mail`, 128-bit rounding uses `math/bits`.

**Spec:** `docs/specs/2026-10-24-core-platform-spec.md` (§3.1, §4, §5, §6, §9); decisions CD-01…CD-41 (Round 1), CD-42…CD-51 (Round 2), CD-52…CD-83 (Round 3) and CD-84…CD-92 (Round 4) in `docs/specs/contract-changes.md` (already in §5). Requirements: `docs/tests/core/06-masters.md` (every MST case), `docs/tests/core/00-fixtures.md` (canonical seed). Rules source: `reference/india-compliance/india_compliance/gst_india/constants/__init__.py` and `.../utils/__init__.py`.

## Review Focus

1. **GSTIN pasted from a PDF or WhatsApp** with lower case, a trailing non-breaking space or a zero-width space. A person expects it stored clean and accepted; spaces inside the GSTIN must give the length error, not be silently removed. Pinned by `TestGSTIN_CopyPasteWhitespace` (Task 2).
2. **Renaming a code to itself in different case** (`shree ` → `SHREE`). A person expects a no-op: no "already used by Party Shree Steel Traders" error against itself and no audit entry. Pinned by `TestMaster_RenameSameCodeNoop` (Task 16).
3. **Two people promoting different addresses to primary billing at the same moment.** The writes serialise; the later one wins and exactly one primary remains, never two and never none. Pinned by `TestAddress_PrimaryUniqueUnderRace` (Task 6) via a partial unique index.
4. **Date of birth equal to today just after midnight IST** (clock 2026-10-23T19:00:00Z = 24-10-2026 00:30 IST). A person expects 2026-10-24 to be accepted, not "in the future" because UTC is still the 23rd. Pinned by `TestEmployee_DOBTodayIST` (Task 14).
5. **One CSV file that adds two new parties with the same GSTIN.** Neither is in the database yet; the preview must still reject row 3 with the MST-044 message naming the party from row 2. Pinned by `TestImport_DuplicateGSTINWithinFile` (Task 20).

## Decisions

**M1 · How masters register with the DocType registry (CD-21).** Every master calls `mstkit.RegisterMaster` from its package `init()`, which calls `doctype.Register` with:
`Series: ""`, `Submittable: false`, `Approvable: false`, `Printable: false`, `HasRoundedTotal: false`, `PluralLabel` (CD-35: "Parties", "Items", "UoMs", "Tax Codes", "Projects", "Sites", "Employees", "Expense Types", "Payment Terms", "Branches", "Addresses", "Contacts"), `Importable` true for the masters D-NUM-25 lists (party, address, contact, item, UoM, tax code, project, site, employee, expense type) and false for company, branch, payment terms; `SearchFields: {"code","name"}` (address: `title`, `city`; contact: `first_name`, `last_name`); `DefaultSort: name asc` on declared fields only (the kernel list adds the `id` tie-breaker, D-NUM-20); the `disabled` field is Filterable (pickers and DefaultFilters); no `Links` for master-to-master foreign keys (LinkSpec is document-to-document; `mstkit.DeleteTx` scans master Link fields itself, CD-167); `Hooks: nil` (§5: masters have no lifecycle hooks; their validation runs in the master's `Service` and in its import `RowFunc`); `Master` = the master's `doctype.MasterLookup`; `ProjectFields: {"id"}` on Project and `SiteFields: {"id"}` on Site (CD-09, CD-64, so a user's project/site restrictions apply to those masters themselves: lists, pickers, export and AUTH-102); `Fields` with the CD-42 extras of M13; and `DefaultRights` from the table below. A non-nil `DocType.Master` is the registry's "master" marker: the table has `disabled` instead of `state` and no `number`; AUTH's matrix offers only read, create, write, delete, export, import (if Importable) and print; `Engine.Do` refuses every lifecycle action for it; DOC validates every link to it through `Master.Lookup` (not found → DOC-032, `Disabled` → DOC-034's wording (CD-38), `Blocked != ""` → that message shown as given, prefixed `Line N: ` on lines, `Warning` → an entry in `doc.Result.Warnings` (CD-68)). DOC shows a linked master as `{Code} {Name}` built from the `MasterInfo` (CD-68; DOC-034 expects "CEMENT-OPC OPC Cement 53 Grade"), so every MST lookup fills both `Code` and `Name`; Address and Contact have no code and return `Code: ""` with the title or full name as `Name`. Master writes never go through `Engine.Do`; they go through the master's `Service`, whose HTTP handlers (Task 22) render with the generic `internal/ui` list and form components.

Production `DefaultRights` (CD-10; role → right → scope, all scopes `all`). Administrator has no rows (AUTH grants it everything through the role). The test seed does not use these; it stays exactly as `00-fixtures.md`, and `msttest` grants what tests need.
