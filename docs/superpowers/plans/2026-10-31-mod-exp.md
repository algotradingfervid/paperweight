## Global constraints

**Packages.**
- `internal/modules/expense`: services, DocTypes, hooks, reports. It never imports `internal/ui`.
- `internal/modules/expense/expensetest`: the module's test environment (real engine, real `auth.Service`, real `files.Store`).
- `internal/modules/expense/web` (package `expenseweb`): screens, docscreen hooks, module routes. May import `internal/ui` (CD-237; M0-6's guard).
- `internal/app`: wiring only.
- `expense` is last in M0-6's module order (`modkit` < `purchase` < `goodsreceipt` < `expense`). It needs nothing from `purchase` or `goodsreceipt`; it imports kernel, masters and `modkit`.

**Data.**
- Migrations `migrations/10350–10499`, the expense range in PO spec §14.5. `expense/sqlc.yaml` lists only its own migrations plus every migration whose tables it reads (CD-117): `01500_employee.sql`, `01550_expense_type.sql`, `01400_project.sql`, `01450_site.sql`, `01300_tax_code.sql`, `01050_company_branch.sql` (Billed to), the users and roles migration (`00100_auth_users.sql`), the attachments, audit and approval-history migrations (E8's approved on and by). Unreleased migrations are edited in place.
- Query names in `queries/*.sql` carry their task's prefix (`E3ReceiptLines`, `E8OpenClaims`, …); shared reads live in E1's `base.sql`. Lanes that each add `queries/<task>.sql` then never clash in the one `dbq` package.
- Every id is `INTEGER PRIMARY KEY AUTOINCREMENT` (CD-156). Line tables have `id`, `parent_id` ON DELETE CASCADE and `line_no` (CD-161).
- Convention columns (`number`, `state`, `created_by`, …) are declared only as read-only fields mapped to themselves (CD-144). Header and line field names are unique per DocType; a line field sharing a header name is `line_<name>` with an explicit `Column` (CD-151). The advance's header `amount` and line `amount` clash: the advance line field is `line_amount`, `Column: "amount"`.
- `less_advance` is a nullable column, and NULL means "as much as the advance allows" (proposed decision 6). `Validate` keeps NULL stored and computes the effective amount, `min(left, total)`, on every save for `net_payable`; `BeforeSubmit` writes the effective amount into the column at submit, so an approved claim always holds a number. A typed 0 with an advance named is refused at submit. The advance is picked on step 1, before any lines exist, so `Less advance can't be more than the total.` is a submit check, not a save check (a create refuses every Validate error, `doc/save.go:78`).
- Computed header fields (`total`, `net_payable`, `period_from`, `period_to`, advance `amount`) are `ReadOnly` and written by `Validate` in its transaction, as `fixture.Claim` does (`internal/fixture/claim.go`). `used_amount` is `System`, `ReadOnly`, `EditableAfterSubmit`, written only by the claim effects.

**Hooks (no principal).** `doctype.Hooks` methods get `(ctx, tx, id)` only.
- DocTypes register at `init` (`doctype/registry.go:40`), so hooks reach their dependencies per database through AD-9's `modkit.Wiring[T]` (M0-27, CD-284): `Wire(d *db.DB, v T)` and `Get(tx *db.Tx) (T, error)`. E1 defines `Deps{Clock clock.Clock; Auth auth.Service; Directory auth.Directory; Files *files.Store; ExpenseTypes *expensetype.Service}` and one package-level `modkit.Wiring[Deps]`; `internal/app`'s `app.New` wires it for its database, and `expensetest` wires it for each test database. Every hook calls `Get(tx)` first and returns its error, so parallel worlds in one binary (internal/app tests, e2e) each get their own `Deps`. No global value, no panic on a second wire. Hook code reads only through the `tx` it is given.
- `Validate` runs on every draft save and again inside submit and approve (`doc/transitions.go` `revalidate`), so it can't tell a save from a submit. Rules the spec marks **Submit** go in `BeforeSubmit`, which runs on submit and on approve (D-APR-15). Field-level submit errors return `doc.Invalid(fields)` (X1), so the check page highlights the rows; whole-document refusals return `doc.Refused(msg)`.
- The acting user is the row's `updated_by`, set before `Validate` runs on create, save and amend (`doc/sqlgen.go:120`, `:157`). Role checks use `auth.Service.HasRoleTx` with `auth.RoleAdministrator`; reads inside the hook use the Tx twins (CD-213, CD-224).
- Line `project_id` and `site_id` are tags for reports: the claim declares no `ProjectFields`/`SiteFields` (spec §3), so the engine doesn't check them against restrictions on save. Accepted per spec §9: the pickers already respect restrictions, and the claim's own scope is own and team.
- `hooks.go` composes every hook from per-task functions, in this order:

| Hook | Claim | Advance |
|---|---|---|
| `Validate` | `validateClaim` (E2; it calls `settleOnSave`, E4) → `checkReceipts` (E3) | `validateAdvance` (E2) |
| `BeforeSubmit` | `checkLock(claim)` (E6) → field errors from `submitClaimFields` (E2) + `submitReceipts` (E3) + `submitAdvanceFields` (E4), returned together as `doc.Invalid` → `checkAdvanceLeft` (E4, which also writes the effective `less_advance`) | `checkLock(advance)` (E6) |
| `ApplyEffects` | `applyClaim` (E4) | nil |
| `ReverseEffects` | `checkLock(claim)` (E6) → `reverseClaim` (E4) | `checkLock(advance)` (E6) → `checkNotPaid` (E9: a paid advance can't be cancelled) |
| `Amount` / `Date` | `amountClaim` / `dateClaim` (E5) | `amountAdvance` / `dateAdvance` (E5) |

**Writes.**
- Every write goes through `db.Write`; cross-record checks read inside it (CD-94).
- Every web write posts `version` (CD-183); module routes too.
- Inside a transaction, Tx twins only (`CanTx`, `CheckLinkTx`, `HasRoleTx`, `files.Store.ListTx`), never a second connection (CD-213, CD-224). The nestcheck gate runs in `make test`.
- The advance's `used_amount` is recomputed from the approved and closed claims naming it, never incremented (D-DOC-13).

**Messages.**
- Each text is copied exactly from spec §5 into a catalogue file owned by its task (`messages_<task>.go`). One condition per message (CD-147). The texts with `{advance}` or `{claim}` name another record only when the viewer can read it (CD-233, CD-240, CD-248; see E6).
- Other packages' refusals are expected by their exact text (CD-142): FILE-045's and FILE-046's (files), MST-031's (`gstin`), MST-120's leaver text (employee), DOC-017's closed text, DOC-052's blocked text, APR's no-one-else text, AUTH's 403 and link refusal (CD-240), M0-7's lock text.

**Tests.**
- Test-first. High tier: a test-writer writes the task's tests from this plan and the test doc; they're committed first; the implementer may not change them.
- Test helpers follow the research report's §2 patterns (CD-271): `expensetest` business-step builders that can stop at draft (`DraftClaim`, `ApprovedClaim`, `ApprovedAdvance`, `PaidAdvance`, `Against(claim, adv, ₹)`), default-merge inputs so a case states only what it cares about, the advance's used and left asserted after every step including cancel (T3), one refusal helper `wantRefused(t, err, text)` that also asserts nothing was written (state, version, used, audit count; T6), one `wantNotNamed(t, text, hidden...)` for hidden-record rules (T7), paise amounts in fuzz seeds (T11), and a stored-state check through the service after each browser flow (T10).
- Restriction-, scope- and eligibility-dependent behaviour has at least one test on the real `auth.Service` (EXP-016, EXP-017, EXP-018, EXP-039 to EXP-041 always).
- Concurrency tests run as non-admin users (CD-213).
- Each named behaviour has a test that fails when its call site is deleted (`make covertouched BASE=<task base> PKGS=...`).
- Test literals that enter a validated API (series templates, money, GSTINs) are checked against the validator first. Both series render at 14 characters (`EX/26-27/00001`, `EA/26-27/00001`).

**UI.**
- Built from `components.*` and `FieldInput` through the docscreen hooks only. No daisyUI classes outside `internal/ui`, no `style=`, inline scripts, `hx-on` or trigger filters.
- No new component unless the approved UX design names it.
- Directors run `make generate` and the `internal/ui` tests from their own session (the Tailwind binary hangs in the agent sandbox; lessons §11). Workers regenerate only `dbq/` (`sqlc`) and single templ files (`go tool templ generate -f`).

**Temp files** carry the task label (`mod-exp-e3-...`).
