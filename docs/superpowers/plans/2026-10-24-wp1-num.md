# WP1-NUM (Numbers, Dates, GST, Lists, CSV) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Run it under `docs/superpowers/plans/2026-10-25-execution-protocol.md` (roles, risk tier per task, review cadence; CD-96).

**Goal:** Fill in `internal/types`, `internal/kernel/gstcalc`, `internal/kernel/list` and `internal/kernel/csvio` so that all 105 P1 NUM test cases (and then the 14 non-e2e P2 cases) in `docs/tests/core/07-numbers-lists.md` pass.

**Architecture:** `types` holds fixed-point `int64` value types with one half-up rounding rule, 128-bit products (`math/bits`), Indian-format parsing and display, business dates, the April financial year and IST time. `gstcalc` is pure functions over `types`: line amount, per-line GST split, document totals, state resolution. `list` compiles a `doctype.DocType` plus a user `Query` plus an `auth.Predicate` into one parameterised SQLite statement and runs it. `csvio` reads UTF-8 CSV into rows, checks every cell, hands each row to the DocType's registered `csvio.RowFunc` inside one `db.Write` transaction (rolled back for a dry run or on any error), and exports through `list`.

**Tech Stack:** Go 1.27.3 standard library only (`math/bits`, `math/big` in tests, `time`, `time/tzdata`, `encoding/csv`, `unicode/utf8`, `strconv`, `database/sql`); `modernc.org/sqlite` v1.61.0 through `internal/platform/db`; `github.com/google/go-cmp` v0.7.0 in tests.

**Spec:** `docs/specs/2026-10-24-core-platform-spec.md` (§2 stack, §3.1 resolutions, §4 layout and rules, §5 contracts, §9 parallel rules); decisions CD-01…CD-41 (Round 1), CD-42…CD-51 (Round 2) and CD-52…CD-77 (Round 3) in `docs/specs/contract-changes.md` (already in §5); those that change this plan are listed under "Contract requests: resolved by". Requirements: `docs/tests/core/07-numbers-lists.md`. Seed values: `docs/tests/core/00-fixtures.md`. Where the test file and the spec differ, the spec wins.

- [ ] **Step 3: Implement `round.go`, `limits.go`, `errors.go`**

`MulDivRound` algorithm (not determined by the signature):
```
sign := sign(a)·sign(b); ua, ub := |a|, |b| as uint64
hi, lo := bits.Mul64(ua, ub)
if hi >= uint64(d) → return 0, false        // Div64 would panic / quotient > 64 bits
q, r := bits.Div64(hi, lo, uint64(d))
if q > math.MaxInt64 → return 0, false       // check before rounding: q++ on MaxUint64 wraps to 0
if 2*r >= uint64(d) → q++                    // half-up on the magnitude = ties away from zero
if q > math.MaxInt64 → return 0, false
return sign·int64(q), true
```
`DivRound`, `RoundTo`, `Rescale` use the same "round the magnitude, reapply the sign" rule.

Grammar (D-NUM-14), applied in this order:
1. Trim spaces, tabs and U+00A0 on both ends. Empty → `ErrEmpty`.
2. Optional `-`; then (Money and Rate only) optional `₹` plus spaces, then optional `-` if none yet. Percent only: optional trailing `%`.
3. Integer part: empty (only when a fraction follows), plain ASCII digits, Indian grouping `^\d{1,2}(,\d\d)*,\d{3}$`, or international `^\d{1,3}(,\d{3})+$`. Optional `.` and zero or more digits (`"5."` and `".5"` are valid, `"."` is not). Anything else → invalid-form message.
4. Strip trailing zeros of the fraction; more digits than the scale → decimal-places message.
5. Range → range message. A negative zero becomes 0.

| Type | Invalid form | Decimal places | Range |
|---|---|---|---|
| Money | `"<input>" is not a valid amount. Write it like 1,234.50 or 1234.50.` | `Amount can have at most 2 decimal places.` | \|v\| > MaxMoney: `Amount is too large. The maximum is ₹10,00,00,00,000.00.` |

| Field type | Allowed ops | Not-allowed message suffix | Value parsing |
|---|---|---|---|
| Text, Select | `=`, `!=`, contains, in, not in, is empty, is not empty | `Use =, contains, in, is empty.` | trimmed text |
| Link, Int, Check | `=`, `!=`, in, not in, is empty, is not empty | `Use =, in, is empty.` | base-10 int64 (link id); Check `0`/`1` |
| Money, Qty, Rate, Percent, Factor | `=`, `!=`, `<`, `<=`, `>`, `>=`, between, in, not in, is empty, is not empty | `Use =, <, >, between.` | matching `types.ParseX`; its message is returned as a `QueryError` |
| Date, Timestamp | `=`, `!=`, `<`, `<=`, `>`, `>=`, between, on or after, on or before, is empty, is not empty | `Use =, between, on or after, on or before.` | `types.ParseDate` |

- Unknown or non-Filterable field: `You can't filter <dt.PluralLabel> by '<field>'.` (CD-35) Disallowed op: `'<op>' can't be used on <Label>. <suffix>` Wrong value count: `Choose a value for <Label>.`
- `col` below is always `<dt.Table>.<Column>` (CD-16). `!=` → `(col IS NULL OR col != ?)`; `not in` → `(col IS NULL OR col NOT IN (…))`; `in []` → `1=0`; `not in []` → `1=1`; text `is empty` → `(col IS NULL OR col = '')`; other types `col IS NULL`.
- `contains` and search: `col LIKE ? ESCAPE '\'` with `%`, `_`, `\` escaped and `%…%` around the trimmed text.
- `between` needs exactly 2 values: one → `Choose both a start and an end date.`; start > end → `The start date must be on or before the end date.`
- Timestamp fields compare against IST day bounds: `= d` → `>= ISTDayStart(d) AND < ISTDayStart(d+1)`; `between a b` → `>= ISTDayStart(a) AND < ISTDayStart(b+1)`; `on or after a`/`>= a` → `>= ISTDayStart(a)`; `on or before b`/`<= b` → `< ISTDayStart(b+1)`; `< d` → `< ISTDayStart(d)`; `> d` → `>= ISTDayStart(d+1)`. Bound args are `Timestamp.String()` values.
- Search: empty after trim → no condition; else OR across `dt.SearchFields`, ANDed with filters. - `ParseSort`: each key must name a Sortable field and the direction must be `asc` or `desc`; otherwise `You can't sort <dt.PluralLabel> by '<field>'.` (with `'<field> <dir>'` when only the direction is bad). `Build` re-checks `q.Sort` (a `doctype.SortKey` naming an unknown or non-Sortable field gets the same message).

- Each key emits `CASE WHEN <col> IS NULL<text: OR <col> = ''> THEN 1 ELSE 0 END, <expr> <ASC|DESC>` so empty values are last in both directions; Text uses `COLLATE NOCASE`; Link fields sort by the target's name: `(SELECT <target>.name FROM <target> WHERE <target>.id = <table>.<col>) COLLATE NOCASE` (all names qualified, CD-16).

**Interfaces:**

- Produces:
  - `const MaxFileBytes = 5 << 20`; `const MaxRows = 5000`.
  - `type FileError struct{ Msg string }` (`Error()` = Msg) for whole-file failures; `Status() int` = 422 and `FieldErrors()` = nil, so `*FileError` satisfies `doctype.HTTPError` (CD-44).
  - `type Sheet struct{ Header []string; Rows []SheetRow }`; `type SheetRow struct{ Num int; Cells []string }` — `Num` is the spreadsheet row number (header = 1).
  - `func ReadSheet(r io.Reader) (*Sheet, error)`
  - `type ColumnMap struct{ Index int; Field *doctype.Field }`; `func MapHeader(dt *doctype.DocType, header []string) ([]ColumnMap, []string, error)` (mapped columns, warnings, error).
  - `func EscapeFormula(s string) string`; `func UnescapeFormula(s string) string`.

`ReadSheet` order of checks: read up to `MaxFileBytes+1` bytes → over: `This file is larger than 5 MB. Split it into smaller files.`; `!utf8.Valid` → `This file isn't saved as UTF-8. In Excel choose Save As → CSV UTF-8 (Comma delimited) and upload again.`; strip a leading BOM; parse with `encoding/csv` (`FieldsPerRecord = -1`, `ReuseRecord = false`); trim every cell; skip records whose cells are all empty; a data row whose cell count differs from the header's: `Row <n> has <cells> values but the header has <header cells>. Check for an unquoted comma.`; data rows > MaxRows: `This file has <FormatCount(n)> rows. Import at most 5,000 rows at a time.`; zero data rows: `The file has no rows to import.`

Row numbers: `Num = startLine − embeddedNewlinesBefore`, where `startLine` comes from `csv.Reader.FieldPos(0)` and `embeddedNewlinesBefore` counts `\n` inside cells of all earlier records. Blank lines therefore count as rows, matching Excel.

`MapHeader`: normalise a header cell by stripping a BOM, trimming, lower-casing, and turning `_` and runs of spaces into one space. It matches a field when it equals the normalised `Field.Label`, `Field.Name`, or `dt.Label + " " + Field.Label` (so "ITEM NAME" → Name). Empty header cells are ignored. A field matched twice: `Column '<Label>' appears twice. Keep one.` A Required Importable field with no column: `Column '<Label>' is missing. Add it to the first row.` A non-matching cell is a warning: `Column '<cell>' isn't a field of <dt.Label> and will be ignored.` A matching but non-Importable field is a warning: `Column '<Label>' can't be imported and will be ignored.`

Formula escape (D-NUM-26): triggers are `=`, `+`, `-`, `@`, `\t`, `\r`. `EscapeFormula` prefixes `'` when the first character is a trigger. `UnescapeFormula` removes a leading `'` only when the next character is a trigger.

2. Inside `DB.Write`, row by row in file order, collect errors in this order: `Auth.Can(…, "create", nil)` denial → `Row <n>: you don't have permission to create <dt.Label>.`; cell check per field type (Money/Qty/Rate/Percent/Factor via `types.ParseX`, Date via `ParseDate`, Check accepts `yes/no/true/false/1/0` in any case and blank = no, else `"<cell>" is not Yes or No.`; Link via code lookup below), each as `Row <n>, column '<Label>': <msg>`; Required empty → `Row <n>: <Label> is required.`; code duplicates (field `code`, compared upper-cased, against earlier rows and `SELECT 1 FROM <table> WHERE upper(<table>.code) = ?`) → `Row <n>: Code <code> is repeated (also on row <m>).` / `Row <n>: Code <code> already exists.`
3. Link cells: `target, _ := doctype.Lookup(field.Link)`; `SELECT <target>.id FROM <target> WHERE <target>.code = ?`. Missing → `<Label> '<cell>' not found. Use an existing <Label> code such as <suggestion>.` where suggestion is the active code with the longest case-insensitive common prefix (ties: alphabetical). Found → `target.Master.Lookup(ctx, tx, id)` (CD-21); `MasterInfo.Disabled` → `<Label> '<cell>' is disabled. Enable it or use another <Label>.` Because earlier rows are already written in the same transaction, a link to a record created by an earlier row resolves.
4.
