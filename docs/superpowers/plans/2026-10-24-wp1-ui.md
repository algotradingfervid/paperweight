# WP1-UI: Design System, Components and Generic Screens, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Run it under `docs/superpowers/plans/2026-10-25-execution-protocol.md` (roles, risk tier per task, review cadence; CD-96).

**Goal:** Build `internal/ui`: tokens and CSS, the asset pipeline, icons, the app shell, every component in design-system §7, the wizard framework, the generic DocType list and document screens, the screen registry used by the overflow sweep, a lint test and a contrast test, and a component gallery checked in a browser at six widths. Every other screen in the app is built from these parts.

**Architecture:** Components are templ functions that take plain Go structs of display strings, so they never format numbers or read the database. Screens that need data (`docscreen`) read through §5 contracts: `doc.Engine.Load` returns a `doc.Record` (CD-43), `doctype.Field` carries list priority, options, max length, hint and wizard step (CD-42), every kernel error implements `doctype.HTTPError` (CD-44), and rights are checked inside the handler with `auth.Service.Can` (CD-46). `docscreen` turns plain record values into display strings with NUM's formatters (CD-33, merged first per CD-53). Only two reads have no §5 contract yet (running a list query, and reading approval and audit history), so they stay behind small UI consumer interfaces (`Lister`, `Extras`) that WP3 adapts (CD-78). Messages across a 303 use WP0's flash (CD-80). Wave 1 tests use `docfake`, `authfake`, `approvalfake` and `filesfake`. CSS and JS are split into files that each task owns. esbuild's Go API bundles them into one hashed `app.<hash>.css` and one hashed `app.<hash>.js`. The outputs are committed and embedded, and a test proves they are current. A gallery (`/_gallery`, imported only by tests and e2e builds) renders every component and screen variant with worst-case values. A browser test, run under the `e2e` tag inside `internal/ui`, checks the gallery for horizontal overflow, axe violations, target size and CSP violations. WP3 reuses the same helpers for the full-route sweep.

**Tech Stack:** Go 1.27.3, `a-h/templ` v0.3.1070, `go-chi/chi/v5` v5.5.0, htmx 2.0.11 (served by WP0 at `web.HTMXURL`), `@alpinejs/csp` 3.17.5 (served by WP0 at `web.AlpineURL`; both content-hashed, CD-47), `evanw/esbuild` v0.28.2 (Go API, build time only, JS bundle), Tailwind CSS v4.3.3 standalone executable (build time only, sha256-pinned) with daisyUI v5.7.50 (`daisyui.mjs` vendored; CD-98, `docs/research/ui-library.md`), `internal/platform/brand` (WP0 Task 7b, CD-99), lucide-static 1.61.0 (vendored SVGs), Inter 4.1 and Noto Sans Devanagari 2.007 (subset woff2), test-only `PuerkitoBio/goquery` v1.13.0 (BSD-3, released 27-08-2026, pushed 21-10-2026), `chromedp/chromedp` v0.21.0, axe-core 4.14.0 (npm `latest` on 24-10-2026, MPL-2.0).

**Spec:** `docs/specs/2026-10-24-design-system.md` (the spec for this WP; every section maps to a task in the coverage table at the end). Task 1 Step 1 re-checks them. A newer stable version is used only after it is recorded in the Task 1 commit message with the reason.
- Product rules (design-system §1): mobile-first (base CSS targets 320 px; larger layouts only via `min-width` media or `@container` queries); **light only** (`color-scheme: light` on `:root` and `<meta name="color-scheme" content="light">`; no `prefers-color-scheme` anywhere); **no horizontal scrolling at any width ≥ 320 px**; complex forms are wizards with a progress bar; open-source only.
- CSP-safe: no `style=` attributes, no inline `<script>` except `type="application/json"`, no `on*=` handler attributes, no `hx-on`, no `js:` in `hx-vals`/`hx-headers`, no `hx-trigger` filters `[...]`, no templ `css`/`script` blocks, no `templ.JSFuncCall`/`templ.ComponentScript`, no `x-html`, and no arrow functions, template literals or `window.`/`document.`/`Math.`/`JSON.`/`console.` inside `x-*` attributes. The lint test (Task 2) enforces all of these.
- **daisyUI (CD-98).** Every component's styling starts from its daisyUI base in design-system §7.1; parts marked "own" are Tailwind `@utility` rules in `internal/ui/css/` (never `@layer components`, which loses to daisyUI's layers nested in `utilities`; research `ui-library.md` §2). daisyUI class names appear only in `internal/ui`; the banned parts in `ui-library.md` §4 never appear. Brand colours, app name and logos come only from `internal/platform/brand` (CD-99); no component hard-codes them.
- `internal/ui/css/tokens.css` and `internal/ui/css/theme.css` (the daisyUI theme, values copied from tokens and checked by a test) are the only files with raw colours or raw lengths. Every target is ≥ 44 × 44 px (`--target-min`), with 48 px in the phone action bar and 8 px gaps. Inputs use 16 px text.
- Copy (design-system §9): sentence case; buttons are verbs; dates `dd-mm-yyyy`; timestamps `24-10-2026 14:45` (CD-33, the only format); money `₹94,164.00`; unnumbered documents `Draft 42`. Kernel-owned wording (403 text, DOC/APR state messages, NUM parse errors) is passed through unchanged and never rewritten.
- Components (`components`, `layout`, `wizard`) take display strings and never format. `docscreen` and the field validators call NUM's §5 parsers and formatters directly (`types.Parse*`, `FormatINR`, `FormatQty`, `FormatRate`, `FormatPercent`, `FormatDate`, `FormatIST`; CD-33, available from Wave 1a per CD-53). Rates show 2 to 4 decimals (`₹62.50`, CD-61). Master links show "{Code} {Name}" (CD-68).
- Errors: handlers map kernel errors only through `doctype.HTTPError` (`Status()`, `FieldErrors()`; 403, 404, 409, 422) and `errors.Is(err, doctype.ErrNotFound)` (CD-44, CD-54; its text is AUTH's "This record doesn't exist or you don't have access to it.", CD-76). Any error UI does not render itself (including `db.ErrBusy`, which is not an `HTTPError`) goes to `web.ErrorFrom(w, r, err)`, which maps `db.ErrBusy` to 503 with its own text (CD-76, CD-81). `web.ErrorFrom` matches its own local `interface{ error; Status() int }` with `errors.As` because `platform/web` imports no kernel package (CD-90); `doctype.HTTPError` satisfies it. UI still maps through `doctype.HTTPError` itself (`docscreen.Classify`) for everything it renders, and never relies on `web.ErrorFrom` for 403/404/409/422 pages.
- Messages across a 303 use WP0's flash (CD-80): handlers call `web.Flash(ctx, level, text)` before redirecting, and `layout.Page` reads `web.TakeFlash(ctx)` and shows success above the `h1` and warnings and errors in `#alerts`. No banner text travels in the URL. The message is `err.Error()`, unchanged; UI writes no error copy of its own.

- CSRF (CD-15): `<body hx-headers='{"X-CSRF-Token":"<token>"}'>` (static JSON) and a hidden `csrf_token` field in every `<form method="post">`. The token comes from `ui.ShellFrom(ctx).CSRF`. WP3 fills it with `authweb.CSRFToken(ctx)`.
- `internal/ui` never imports AUTH's `internal/kernel/auth/web` (`authweb`) or its subpackages (CD-88). The import runs the other way: AUTH's `internal/kernel/auth/web/views/` and `web/screens/` import `internal/ui/layout` and `internal/ui/components`. `TestUI_NoAuthwebImport` (Task 16) enforces it.
- Expired or missing sessions (CD-17, CD-63): htmx 401 responses carry `HX-Redirect` to `/signin?next=…`, which htmx 2.0.11 follows before `responseHandling` (`htmx.js:4884`). No config entry is needed. Sign-in and sign-out are AUTH's `/signin` and `/signout`; the shell's sign-out is a POST form to `/signout`.
- Every handler that returns a fragment for `HX-Request` sets `Vary: HX-Request` (`ui.Render`).
- Generated files are committed: `*_templ.go`, `internal/ui/icons/icons_gen.go`, `internal/ui/assets_gen.go`, `internal/ui/static/*`. Regenerate with `make generate` (runs `go generate ./...` before sqlc and templ, CD-45). Browser tests run with `make e2e` (`go test -tags e2e ./...`, CD-45).
- Tests: HTML assertions use `uitest.Render` (goquery). Browser tests use the `e2e` build tag, live in `internal/ui/uibrowser`, are named `TestGalleryBrowser_*`, and are not test-case IDs (CD-40). Every `TestE2E_*` belongs to WP3 under `e2e/`.
- `testkit.Clock()` (2026-10-24T05:00:00Z) wherever a time is needed. No wall clock.

## Review Focus

1. **Worst-case values at 320 px** (100-character names, 60-character unbroken codes, a 253-character email, `₹99,99,99,999.99`, 500 lines, a 400-character error). Expect no sideways scroll and nothing clipped. Pinned by `TestGalleryBrowser_NoHorizontalOverflow` over gallery pages fed by `uitest.Long*` (Task 15).
2. **User text containing markup** (`<script>`, `<img onerror>`) in list rows, history changes, banners, picker rows and toasts. Expect it shown as text. Pinned by `TestComponents_EscapeUserText` (Task 8), `TestHistory_EscapesValues` (Task 13) and `TestGalleryBrowser_ToastTextOnly` (Task 15, where app.js builds the toast with `textContent`).
3. **Double tap on "Save and continue" on a slow phone.** Expect one request: the button disables and reads "Saving…". Pinned by `TestButton_SubmitBusyAttributes` (Task 7) and `TestGalleryBrowser_DoubleSubmitSendsOnce` (Task 15).
4. **Browser Back after a wizard step.** Expect a full GET of the saved draft, never a cached snapshot or a bare fragment. Pinned by `TestLayout_HTMXConfig` (Task 6), `TestRender_VaryAndFragment` (Task 6) and `TestWizardForm_GetIsFullPageWithoutHXRequest` (Task 14).
5. **A user who may only read the document.** Expect no empty sticky action bar covering content and no "More actions" heading with nothing under it. Pinned by `TestActions_ReadOnlyUserGetsNoBar` (Task 13).
