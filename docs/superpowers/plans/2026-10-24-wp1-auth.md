# WP1-AUTH (Identity & Permissions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `internal/kernel/auth`: users, argon2id passwords, lockout, server-side sessions, CSRF, the role × DocType rights matrix with `own` / `team` / `all` scope, strict Project/Site restrictions, the frozen `auth.Service` contract (Can / Scope / CheckValues / CheckLink / UsersWithRight / HasRole / User / DisableUser / EnableUser, plus `WithPrincipal` / `PrincipalFrom`), and the sign-in, setup, account and user-admin HTTP handlers in `internal/kernel/auth/web`. AUTH also owns two admin screens built from `internal/ui` components: the user restrictions editor and the read-only "Who can…" view (CD-49; Tasks 19–20), and it restyles its own sign-in, setup, password, session and message pages in `web/views` from the same components (CD-88; Task 21). Tasks 19–21 start after WP1-UI merges. Done means every AUTH P1 case in `docs/tests/core/01-auth.md` that does not need another WP's real implementation passes (CD-40; see "Exit criteria").

**Architecture:** One concrete `*auth.Auth` (built by `auth.New(Deps)`) implements `auth.Service` plus the user, matrix and sign-in operations. Permission metadata comes from the DocType registry in `internal/kernel/doctype` (`OwnerField`, `EmployeeField`, `ProjectFields`, `SiteFields`, `DefaultRights`; CD-02, CD-09). Employee links, reporting lines and Project/Site codes come from `auth.Directory` (CD-13), facts about a linked record from `doctype.InfoSource` (CD-05), and audit entries go to an `audit.Writer` (CD-03). Sessions use `scs/v2` with an AUTH-owned `scs.CtxStore` over a `sessions` table that stores only token hashes and enforces expiry from the injected clock (CD-14). HTTP routes are wrapped in declared guards (`Right` / `Self` / `Admin` / `Public`, plus `CheckedInHandler` for the generic `/doc/{doctype}/…` routes whose handlers call `Can` themselves, CD-46) that a route-inventory test walks with `chi.Walk`. Every AUTH error that reaches a handler implements `doctype.HTTPError` (CD-44). Channel behaviour that other WPs own (lists, print, export, import, API) is tested here through a **probe router** in `web/webtest`: a reference implementation built only from AUTH's contract. WP3 points the same tests at the real router.

**Tech Stack:** Go 1.27.3 · `modernc.org/sqlite` v1.61.0 · `sqlc` v1.31.1 · `pressly/goose/v3` v3.29.0 · `go-chi/chi/v5` v5.5.0 · `alexedwards/scs/v2` v2.9.0 · `golang.org/x/crypto/argon2` v0.58.0 · `golang.org/x/text/unicode/norm` and `golang.org/x/term` (CD-18) · SecLists `10k-most-common.txt` (MIT, embedded; CD-18) · `a-h/templ` v0.3.1070 · `google/go-cmp` v0.7.0.

**Spec:** `docs/specs/2026-10-24-core-platform-spec.md` (§2 stack, §3.1 R3/R4, §4 layout and import table, §5 contracts, §9 parallel rules) and the decisions in `docs/specs/contract-changes.md` (CD-01 to CD-92). Screens follow `docs/specs/2026-10-24-design-system.md` §7 (components) and §8.6 (rights screens). The requirements are in `docs/tests/core/01-auth.md`, and the values come from `docs/tests/core/00-fixtures.md`. Where the two differ, the spec wins, then the fixtures (R5).

Add `golang.org/x/text` and `golang.org/x/term` at their latest stable versions (CD-18) and record the versions in the Task 1 commit message.
- Do **not** use `scs/sqlite3store` (CD-14). AUTH owns the `sessions` table and its `scs.CtxStore`.
- argon2id: memory 19456 KiB, iterations 2, parallelism 1, salt 16 random bytes, key 32 bytes. Encoding: PHC `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<key>`, both parts base64 `RawStdEncoding`.
- Passwords: NFC-normalise before hashing and checking (`norm.NFC.String`). Length is counted in runes after NFC: 10 to 256. **Never trim passwords.** Emails: `strings.TrimSpace` then `strings.ToLower`.
- Lockout: 5 failures per account key or 50 per IP within 15 min. The window starts at the first failure. Keys are `acct:`+hex(SHA-256(normalised email)) and `ip:`+IP. The plain email is never stored.
- Sessions (CD-14): a 32-byte random token (scs) with `HashTokenInStore=true`, so `token_hash` = base64url(SHA-256(token)). Expiry is 12 h idle (inclusive: exactly 12 h is still valid) or 7 days absolute (inclusive), enforced by the server only. Cookie: `HttpOnly`, `SameSite=Lax`, `Path=/`, no `Domain`, `Persist=false` (no `Expires`/`Max-Age`: a browser-session cookie). Over HTTPS: name `__Host-session` with `Secure`. Over HTTP: name `session` without `Secure`.
- Signed-out handling (CD-17): a browser GET gets 303 to `/signin?next=<url.QueryEscape(RequestURI)>`. HTMX (`HX-Request: true`, which also gets `HX-Redirect` with the same URL), `/api/*` and every non-GET request get 401. The body is "Your session has expired. Sign in again." when a session was presented, else "Sign in to continue.". The sign-in page lives at `/signin` and sign-out at `/signout`; every redirect is 303 (CD-63).
- Stored timestamps are `TEXT` fixed-width UTC `2006-01-02T15:04:05.000Z`, written by `auth.FormatTime`. Timestamps shown to people use `types.FormatIST` ("24-10-2026 10:30", CD-33). NUM's `internal/types` merges first (Wave 1a, CD-53), so rebase onto it before Task 16; AUTH-044 asserts the rendered text (Task 16).
- Every write goes through `db.Write` (BEGIN IMMEDIATE). `tx.SQL()` returns `db.DBTX` (CD-06), and each package builds its own sqlc queries with `dbq.New(tx.SQL())`. The sqlc config lives in `internal/kernel/auth/sqlc.yaml`, queries in `queries/` and generated code in `dbq/`. Do not use `right` as a column name (it is an SQLite keyword); use `right_name`.
- `Can`, `Scope`, `CheckValues`, `CheckLink`, `UsersWithRight` and `HasRole` take no `tx`. When they need `Directory` or `InfoSource` (which take `tx`, CD-13/CD-05), they open their own `a.db.Read`.
- Team membership (`Directory.DirectReports`) is read on every check and never cached with the matrix: MST changes reporting lines and employee status without bumping AUTH's `perm_version`.
- Tests never read the wall clock. Use WP0's `*clock.Fixed` (`clock.NewFixed`, `Set`, `Advance`). The default instant is `authtest.T0 = 2026-10-24T05:00:00Z` (10:30 IST).

## Review Focus

These inputs are implied by the spec, but no 01-auth case exercises them directly. Each line names the owning task's extra test.

1. **Session fixation.** An attacker plants an anonymous session cookie, then the victim signs in. Expected: the token changes at sign-in, and the pre-sign-in token resolves to nobody. Test `TestLogin_RenewsSessionToken` (Task 11).
2. **Revocation racing an in-flight request.** Session B is revoked (password change, disable) while one of B's requests is still running. Expected: B's end-of-request commit must not re-create B's row. Test `TestSession_RevokedNotResurrectedByInFlightCommit` (Task 9).
3. **Two administrators demote or disable each other at the same moment.** Expected: exactly one call succeeds, and at least one enabled Administrator remains. Test `TestUser_AtLeastOneAdmin_Concurrent` (Task 7).
4. **Behind the reverse proxy (Caddy), every request has the proxy's IP.** Expected: the per-IP block uses `X-Forwarded-For` only when `Config.TrustProxy` is set, and otherwise `RemoteAddr`. Without this, one office's failures would block everyone. Test `TestClientIP_TrustedProxyOnly` (Task 10).
5. **Whitespace in credentials.** Email `"priya@vardhan.test\t"` is trimmed, but the password `" Correct-Horse-42"` is not trimmed and must fail. Test `TestLogin_PasswordNotTrimmed` (Task 8).
6. **Team scope going stale.** A reporting line or employee status changes in MST while the manager is signed in. Expected: the next check uses the new reporting line, with no sign-out and no `perm_version` bump. Covered by AUTH-118 `TestTeamScope_LeftEmployeeIgnored` (Task 15), which flips Suresh's status between requests.

### Task 6: Service — Scope predicate

**Files:** Create `internal/kernel/auth/scope.go`. Test: `scope_test.go`.

**Interfaces:**
- Produces `Scope(ctx, p, doctype, r) (Predicate, error)`, following CD-16: columns qualified with the DocType's table name, lines reached with `EXISTS (… WHERE <lines>.parent_id = <table>.id …)`, `SQL == ""` means no filter. Administrator → `Predicate{}`. If the grant for `r` or for read is missing → `DeniedError{r}`. Otherwise the predicate is the AND of:
  - the scope clause for read when read is own or team, and for `r` when `r` is own or team (`O` = `ownerColumn(dt)`, `E` = `dt.EmployeeField`):
    - own: `("T"."O" = ?` [`OR "T"."E" = ?` if the DocType has an employee field and `EmployeeForUser` finds one]`)`
    - team: the own clause, plus `OR "T"."E" IN (?,…)` over `DirectReports(me)` (omitted when the list is empty)
  - for each restricted dimension D, with `H` = header columns and `L` = line columns from `dimColumns(dt, D)`:
    - each header column h: `("T"."h" IS NULL OR "T"."h" IN (?,…))`
    - each line column l: `NOT EXISTS (SELECT 1 FROM "Lines" WHERE "Lines"."parent_id" = "T"."id" AND "Lines"."l" IS NOT NULL AND "Lines"."l" NOT IN (?,…))`
    - strict: `("T"."h1" IS NOT NULL OR … OR EXISTS (SELECT 1 FROM "Lines" WHERE "Lines"."parent_id" = "T"."id" AND ("Lines"."l1" IS NOT NULL OR …)))`

  Clauses are joined with ` AND `, and args are in clause order. `Directory` is read inside `a.db.Read`.
