# WP1-DOC: Document Engine, Audit Store and Fixture DocTypes, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Run it under `docs/superpowers/plans/2026-10-25-execution-protocol.md` (roles, risk tier per task, review cadence; CD-96).

**Goal:** Build the generic document kernel: the DocType registry (`internal/kernel/doctype`), the F5 + R2 state machine engine (save, submit, withdraw, approve, reject, revise, close, cancel, amend, delete) running each action as one `BEGIN IMMEDIATE` transaction, linked-document checks, declared roll-ups, `Info`, `Load` and `References` for other packages, the append-only audit store, and the test-only `fixture.Order` / `fixture.Receipt` / `fixture.Claim` DocTypes that prove the whole lifecycle.

**Architecture:** Registry types live in `internal/kernel/doctype` (CD-02), which imports only `types` and `platform/db`; `doc` re-exports them as aliases, so `auth`, `naming`, `approval`, `files`, `print`, `list` and `csvio` read the registry without importing `doc`. Masters register as DocTypes with a `Master` lookup (CD-21), and DOC validates every link to a master through it. The engine (`doc.NewEngine`) builds SQL for each registered DocType from its field list (identifiers are checked at `Register`). It parses the string form values in `ActionInput`, calls module `Hooks`, and reaches AUTH, NAM, APR and FILE only through the §5 interfaces, following the DOC ↔ APR call protocol in §5 (CD-23). The engine also implements `doctype.InfoSource` (CD-05), `References` (CD-22) and `Load` (CD-43, the form values the UI renders), and every error it creates implements `doctype.HTTPError` (CD-44). Every change and transition is written through an `audit.Writer` (CD-03) to `audit_log` in the same transaction. Fixture DocTypes, their stand-in master DocTypes, the test doubles and a harness live in `internal/fixture`, and the fixture tables are test-only migrations (the same pattern as `internal/testkit/migrations`).

**Tech Stack:** Go 1.27.3, `modernc.org/sqlite` v1.61.0, `sqlc` v1.31.1 (audit queries), `pressly/goose/v3` v3.29.0, `google/go-cmp` v0.7.0, Go native fuzzing. No other dependencies. (Browser tests are WP3's, CD-40.)

**Spec:** `docs/specs/2026-10-24-core-platform-spec.md` (§2, §3.1 R1/R2/R4/R5/R6/R7/R8, §3.2, §4, §5, §8, §9) and the decisions in `docs/specs/contract-changes.md` (Rounds 1–3, CD-01…CD-73, plus CD-79, CD-80, CD-82 and Round 4's CD-84). Requirements: `docs/tests/core/03-document.md` (DOC-001…DOC-106) with values from `docs/tests/core/00-fixtures.md`. Builds on `docs/superpowers/plans/2026-10-24-wp0-foundation.md` (Task 3 `db`, Task 5 contracts and fakes, Task 6 `testkit`, Task 7 `checktestids`).

## Review Focus

1. **Reasons with surrounding spaces or non-Latin text.** A reason `"  ab  "` should be trimmed first and fail the 3-character minimum. A 500-character Devanagari reason (1,500 bytes) should be accepted, because lengths are counted in characters. Test: `TestDoc_Reason_TrimmedAndCountedInRunes` (Task 10).
2. **A form value that can't be read** (`qty="12.5.3"`, `credit_days="3O"`, `order_date="24/10/2026"`, `supplier_id="abc"`). Expected: a field error for each value naming its field, no panic, nothing written. Test: `TestDoc_Validate_UnreadableValue` (Task 3).
3. **A hook that panics.** Expected: the engine recovers the panic, the transaction rolls back, a plain error is returned and the server keeps running. Test: `TestDoc_HookPanic_RollsBack` (Task 12).
4. **Two lines of one receipt on the same order line.** Expected: the roll-up adds both lines, and the order gets exactly one `effect` audit row and one version bump. Test: `TestDoc_RollUp_TwoLinesSameTarget` (Task 12).
5. **A clock returning a non-UTC time** (`Asia/Kolkata`). Expected: `created_at`, `updated_at` and audit `at` are still stored as UTC `…Z`. Test: `TestDoc_Timestamps_StoredUTC` (Task 6).
6. **The APR call protocol drifting from §5 (CD-23, CD-52).** Expected: `Open` on every approvable submit, `Record` only with `approve`/`reject`/`revise`/`withdraw`, for approve and reject the visibility check, then `CheckApprover`, then the from-state guard, and no `Can(approve)`; no APR call on delete. Tests: `TestDoc_AprCallProtocol` (Task 10), `TestDoc_ApproveReject_CheckOrder` (Task 9).
7. **A form value that doesn't survive `Load` → save.** Expected: feeding `Record.Values`/`Lines` straight back as `ActionInput` changes nothing (no version bump, no audit row); read-only keys such as `received_qty` are ignored. Test: `TestDoc_Load_RoundTripIsNoOp` (Task 7).

**Document table convention** (stated in the `doctype` package comment; the fixture migrations follow it):
- Header: `id INTEGER PRIMARY KEY`, `number TEXT UNIQUE` (NULL until first approval), `state TEXT NOT NULL DEFAULT 'draft' CHECK (state IN ('draft','pending_approval','approved','closed','rejected','cancelled'))`, `state_reason TEXT NOT NULL DEFAULT ''`, `amended_from_id INTEGER REFERENCES <table>(id)`, `amendment_root_id INTEGER`, `amendment_no INTEGER NOT NULL DEFAULT 0 CHECK (amendment_no BETWEEN 0 AND 9)`, `version INTEGER NOT NULL DEFAULT 1`, `created_at TEXT NOT NULL`, `created_by INTEGER NOT NULL`, `updated_at TEXT NOT NULL`, `updated_by INTEGER NOT NULL`, then one column per header Field. Unique index `ON <table>(amended_from_id) WHERE amended_from_id IS NOT NULL` (one live amendment).
- Lines: `id INTEGER PRIMARY KEY`, `parent_id INTEGER NOT NULL REFERENCES <table>(id) ON DELETE CASCADE`, `line_no INTEGER NOT NULL`, then one column per line Field. The header `version` covers its lines.
- Declared column types are only `INTEGER`, `TEXT` and `BLOB` (CD-34). Text and Select columns are `TEXT NOT NULL DEFAULT ''`. Number, date, timestamp and link columns are nullable. Check is `INTEGER NOT NULL DEFAULT 0`. Roll-up columns are `INTEGER NOT NULL DEFAULT 0`.

**Form value format** (`ActionInput.Values` and `ActionInput.Lines`): Text is verbatim. Select is one of the field's `Options`, verbatim. Int is a base-10 integer. Money, Qty, Rate, Percent and Factor are plain decimals with a dot, no grouping and no symbol, with at most their scale's decimals (`"94164.00"`, `"1200.000"`, `"62.5000"`, `"18"`). Date is `YYYY-MM-DD`. Timestamp is UTC `2006-01-02T15:04:05.000Z`. Check is `true`/`false`. Link is the id in base 10. `""` means empty. A key that is absent means "not provided" (defaults apply). In a line map, the key `id` carries the line id (absent or `""` means a new line). `Deps.ParseValue` can replace `PlainValue`, which WP3 may use to plug in NUM's parsers (`types.ParseMoney` and friends, CD-33) for user-formatted text. `Engine.Load` returns values in the same format (CD-43) through `FormatPlain`, always with the scale's full decimals (`"1200.000"`, `"62.5000"`, `"94164.00"`, Percent `"18.000"`), so a `Record` can be sent back as an `ActionInput` unchanged.

**Link semantics** (stated in the `doctype` package comment): a `Field` of type Link holds the id of a record of the DocType named in `Field.Link`. When that DocType has a `Master`, DOC validates the value through `Master.Lookup` (CD-21). A `LinkSpec{Field, Target, OnLine}` declared on a source DocType marks a document-to-document link used for source-state checks and cancel blockers: with `OnLine`, `Field` is a line field holding a `Target` **line** id; without it, a header field holding a `Target` header id. A `RollUp` is declared on the source DocType; `JoinField` is a source line field holding a target line id. Master display in messages and `Info.Party` is `{Code} {Name}` everywhere (CD-68), e.g. `RAJKOT Rajkot Castings`, `CEMENT-OPC OPC Cement 53 Grade`; a master without a code shows its name only (CD-82); the audit stores `{id, code}` only (DOC-087).

**`Do` pipeline** (engine.go). The order is fixed:
1. Look up the DocType. Unknown or not `IsDocument()` → `KindNotFound` `This document no longer exists. It may have been deleted.` (`Err: doctype.ErrNotFound`).
2. Run in `db.Write`, with `defer recover()` inside the callback converting a panic to `fmt.Errorf("doc: internal error in %s %s: %v", doctype, a, r)` so the transaction rolls back (Review Focus 3).
3. `a == ActionSave && id == 0` → create path.
4. `LoadDoc` (missing → `KindNotFound`, same message).
5. Rights (CD-52):
   - `a` is approve or reject → visibility only: `Auth.Can(ctx, p, doctype, "read", recordRef(dt, d))`, error returned unchanged (AUTH gives `auth.ErrNotFound`, 404, for a record outside the user's read scope). DOC does **not** call `Can(approve)`; APR's `CheckApprover` owns the approve right and its messages.
   - every other action → `Auth.Can(ctx, p, doctype, right(a), recordRef(dt, d))`.
6. `a` is approve or reject → `Approval.CheckApprover(ctx, tx, p, doctype, id)`; its error is returned unchanged. This runs after the visibility check and **before** DOC's from-state guard (CD-23, CD-52), so APR's own wording wins in production.
7. `a == ActionSubmit && d.State != StateDraft && in.Version != d.Version` → `KindRefused` `{X} has already been submitted.` (X = `naming.Label(d.Number, d.ID)`).
8. `guard(d.State, a, X)` (Task 8); approve or reject outside `pending_approval` → `e.notWaiting(ctx, tx, d, X)` (Task 8).
9. `in.Version != d.Version` → `KindStale` `Someone else changed {X} after you opened it. Reload it and make your changes again.`
10. Dispatch. Every header UPDATE ends `WHERE id = ? AND version = ?` and sets `version = version + 1, updated_at = ?, updated_by = ?`. Zero rows affected → the stale error.
11. `errors.Is(err, db.ErrBusy)` from `db.Write` (CD-08) → `&Error{Kind: KindBusy, Message: db.ErrBusy.Error(), Err: db.ErrBusy}` ("The system is busy. Please try again in a moment.").

### Task 12: Roll-ups, effect audit, rollback on hook failure

**Files:** Modify `internal/kernel/doc/rollup.go`. Create `internal/kernel/doc/rollup_test.go`, `tx_test.go`.

**Interfaces:** `func (e *engine) recomputeRollUps(ctx, tx, p, dt, d Doc, number, cause string) error`.

**Algorithm** (recompute, never increment; D-DOC-13):
1. For each `r` in `dt.RollUps`: `ids := SELECT DISTINCT <JoinField> FROM <dt.lines> WHERE parent_id=? AND <JoinField> IS NOT NULL`.
2. For each id:
   - `before, line_no, parent := SELECT <TargetField>, line_no, parent_id FROM <T.lines> WHERE id=?`
   - `after := SELECT COALESCE(SUM(sl.<SourceField>),0) FROM <dt.lines> sl JOIN <dt.table> sh ON sh.id=sl.parent_id WHERE sl.<JoinField>=? AND sh.state IN ('approved','closed')`
   - If they differ, UPDATE the line and collect `audit.Change{Field: TargetField, LineNo: line_no, LineID: id, Before: before, After: after, Op: "set"}` under its parent.
3. For each changed parent, by id: `UPDATE <T.table> SET version=version+1, updated_at=?, updated_by=? WHERE id=?`. Then audit `Action "effect"`, `By p.ID`, `CausedBy &audit.Ref{DocType: dt.Name, DocID: d.ID, Number: number, Action: cause}`, with the collected changes. The target's state is untouched.

### Task 14: Lifecycle table and fuzz invariants

**Files:** Create `internal/fixture/lifecycle_test.go`, `fuzz_test.go`.

**Fuzz model:**
- **Decoding.** Input is read 3 bytes at a time. `op = b0 % 12` picks one of createOrder, createReceipt, save, submit, withdraw, approve, reject, revise, close, cancel, amend, delete. `target = b1 % len(docs)`. `b2 % 8 == 0` injects `Probe.Fail` on one of BeforeSubmit, ApplyEffects or ReverseEffects (rotating). Order amount is `b2 * 1000.00`, so orders at ₹50,000 and above need approval. Limits: 2 orders × 3 lines, ≤ 6 receipts. Receipt lines point at order line `b2 % 6` with qty `b2%20+1`. Saves set `remarks` to the step index. Reasons are `"fuzz reason"`.
- **Model limits (CD-156).** Inputs are capped at 64 steps; receipt amendments count toward the 6-receipt limit, order amendments don't count toward the 2-order limit; the fault hook rotates once per injection.
- **Invariants after every step:**
  - (a) Every order line's `received_qty` equals the SUM of qty over approved/closed receipt lines.
  - (b) No pending, approved or closed receipt has a line on a cancelled order.
  - (c) Every document outside draft equals its snapshot from when it left draft, excluding `received_qty`.
  - (d) `audit.Count` equals the model count. Each successful create, save, submit, withdraw, approve, reject, revise, close, cancel and delete adds 1, amend adds 2, plus 1 per order whose `received_qty` changed in the step. A failed action adds 0.
  - The fuzz harness also checks after every step that each `Approvals.Calls` entry is one of `APR.Evaluate`, `APR.Open`, `APR.CheckApprover` or `APR.Record:<approve|reject|revise|withdraw>` (CD-23).
  - (e) Every previously seen audit row is byte-identical.
  - (f) `number != ""` exactly when the state is approved, closed or cancelled. Non-amendment numbers per prefix are exactly `1..N`.
