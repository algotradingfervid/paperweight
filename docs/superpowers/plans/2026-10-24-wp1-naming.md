# WP1-NAM Naming Series Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Run it under `docs/superpowers/plans/2026-10-25-execution-protocol.md` (roles, risk tier per task, review cadence; CD-96).

**Goal:** Implement `internal/kernel/naming`: series templates, gapless per-prefix counters, number assignment at first approval, amendment suffixes, admin series/counter settings and the GST document-number validator, so that every P1 case in `docs/tests/core/02-naming.md` passes. NAM also owns the Settings → Numbering screen (list + template preview), built from `internal/ui` components after WP1-UI merges (CD-49; Task 18).

**Architecture:** A pure template layer (parse, validate, render, prefix) sits under a small SQLite store of three NAM-owned tables: `naming_series` (one template per DocType), `naming_counters` (last number per DocType × rendered prefix, incremented by one UPSERT…RETURNING) and `naming_issued` (an append-only ledger of every number given, with unique indexes that act as the duplicate backstop). `Assign`/`AssignAmendment` run inside the caller's `db.Write` transaction, so a failed approval rolls the counter back. Because DOC is built in parallel, integration tests drive NAM through a test-only lifecycle harness that calls NAM exactly where spec §3.2 says DOC will.

**Tech Stack:** Go 1.27.3, SQLite via `modernc.org/sqlite` v1.61.0 (through `internal/platform/db` only), `pressly/goose/v3` v3.29.0 migrations, `sqlc` v1.31.1, `google/go-cmp` v0.7.0 (+ `cmp/cmpopts`) in tests. No new dependencies.

**Spec:** `docs/specs/2026-10-24-core-platform-spec.md` (§2 stack, §3.1 R1/R4/R5, §3.2 state machine, §4 layout, import table and data conventions, §5 `naming` contracts including `Admin` and the package functions, §9 parallel rules). Decisions: `docs/specs/contract-changes.md` (Round 1: CD-03, CD-04, CD-06, CD-07, CD-08, CD-27, CD-28, CD-40, CD-41; Round 2: CD-44, CD-49; Round 3: CD-53, CD-54, CD-56, CD-57, CD-66; Round 4: CD-86 apply here). The screen follows `docs/specs/2026-10-24-design-system.md` §7 (components), §8.3 (numbering settings is a single-page form) and §9 (copy). Requirements: `docs/tests/core/02-naming.md`; fixtures: `docs/tests/core/00-fixtures.md`. Where the test file and the spec differ, the spec wins.

- Gapless: the counter increment, the ledger row and the caller's state change share one transaction. Numbers are never reused, renamed or reverted.

## Review Focus

These six inputs follow from the spec but no case in `02-naming.md` tests them. Each has a test in its owning task.

1. **Zero or missing document date passed to `Assign`/`Preview`.** Expect `"A document date is needed to give it a number."`, with no counter row and no ledger row. Task 6: `TestAssign_RejectsZeroDate`.
2. **A DocType with no series row** (the registry never called `EnsureSeries`). Expect `"No numbering series is set up for fixture.Unknown. Ask an Administrator."` (CD-66) and the caller's transaction rolls back. Task 6: `TestAssign_UnknownDocType`.
3. **Lower-case or padded template typed by an admin** (`{fy}`, `" PO/{FY}/{#####} "`). Expect `{fy}` to be rejected with the unknown-part message that names `{fy}`, and surrounding spaces to be trimmed before validation and storage. Task 2: subtest `TestTemplate_Validate/lowercase_token`. Task 11: `TestSettings_TrimsTemplate`.
4. **Empty template.** Expect `"Series must have a number part, for example {#####}."` and no panic. Task 2: subtest `TestTemplate_Validate/missing_number` includes `""`.
5. **A literal prefix that renders the same as another DocType's token prefix** (GRN set to `PO/26-27/{####}` while PO uses `PO/{FY}/{#####}`). Expect it to be rejected when saved, with the duplicate-prefix error, not to fail later at approval. Task 11: subtest `TestSettings_DuplicatePrefix/literal_vs_token`.
6. **`SetCounter` with a prefix the current template can never render** (§5 `SetCounter` takes a rendered prefix, CD-28; e.g. `PUR/26-27/` while PO uses `PO/{FY}/{#####}`, or `PO/26-27` without the slash). Expect `"Prefix PUR/26-27/ doesn't match series PO/{FY}/{#####}."` (`ErrPrefixMismatch`), no counter row and no audit entry. Task 11: `TestSettings_SetCounterPrefixMismatch`.
